# 작업 목록: GitHub 기반 테크 블로그

**입력**: `/specs/001-github-jekyll-chirpy/`의 설계 문서
**사전 요구사항**: plan.md, spec.md (사용자 스토리), research.md, data-model.md, contracts/post-schema.yaml

**테스트**: 이 프로젝트는 정적 사이트이므로 자동화된 단위 테스트 대신 수동 브라우저 테스트와 빌드 검증을 사용합니다.

**구성**: 작업은 각 스토리의 독립적인 구현과 검증을 가능하게 하기 위해 사용자 스토리별로 그룹화됩니다.

## 형식: `[ID] [P?] [Story] 설명`
- **[P]**: 병렬 실행 가능 (다른 파일, 종속성 없음)
- **[Story]**: 이 작업이 속한 사용자 스토리 (예: US1, US2)
- 설명에 정확한 파일 경로 포함

## 경로 규칙
- 프로젝트 루트: `tech_blog/`
- 설정 파일: `_config.yml`
- 포스트: `_posts/YYYY-MM-DD-title.md`
- 페이지: `_tabs/about.md`, `_tabs/archives.md` 등
- 워크플로우: `.github/workflows/pages-deploy.yml`
- 이미지: `assets/img/`

## Phase 1: 설정 (공유 인프라)

**목적**: 프로젝트 초기화 및 Ruby/Jekyll 환경 구성

- [ ] **T001** [P] GitHub에서 Chirpy Starter 템플릿으로 새 저장소 생성
  - 저장소 이름: `USERNAME.github.io` 형식
  - Public 저장소로 설정
  - 로컬에 클론: `git clone https://github.com/USERNAME/USERNAME.github.io.git`

- [ ] **T002** [P] 로컬 개발 환경 설정
  - Ruby 2.7+ 설치 확인: `ruby -v`
  - Bundler 설치: `gem install bundler`
  - 프로젝트 의존성 설치: `bundle install`

## Phase 2: 기초 작업 (블로킹 사전 요구사항)

**목적**: 모든 사용자 스토리가 의존하는 블로그 핵심 설정

**⚠️ 중요**: 이 단계가 완료될 때까지 사용자 스토리 작업을 시작할 수 없습니다

- [ ] **T003** 블로그 기본 설정 파일 구성 (`_config.yml`)
  - `lang: ko-KR` 설정
  - `timezone: Asia/Seoul` 설정
  - `title`, `tagline`, `description` 설정
  - `url: https://USERNAME.github.io` 설정 (USERNAME 치환)
  - `github.username` 설정
  - `social.name`, `social.email`, `social.links` 설정

- [ ] **T004** GitHub Actions 워크플로우 파일 생성 (`.github/workflows/pages-deploy.yml`)
  - Ruby 3.2 설치 단계
  - Jekyll 빌드 단계 (`bundle exec jekyll b`)
  - HTMLProofer 테스트 단계
  - GitHub Pages 배포 단계
  - 트리거: `push` to `main` branch

- [ ] **T005** 로컬 빌드 테스트
  - 명령어 실행: `bundle exec jekyll serve`
  - 브라우저에서 `http://localhost:4000` 접속 확인
  - Chirpy 테마 기본 레이아웃 표시 확인
  - 설정한 제목/설명 표시 확인

**체크포인트**: 기초 준비 완료 - 로컬에서 빈 블로그가 정상 작동하며 이제 사용자 스토리 구현을 시작할 수 있습니다

## 종속성 및 실행 순서

### 단계 종속성

- **설정 (Phase 1)**: 종속성 없음 - 즉시 시작 가능
- **기초 작업 (Phase 2)**: 설정 완료에 종속 - 모든 사용자 스토리 차단
- **사용자 스토리 (Phase 3-8)**: 모두 기초 작업 단계 완료에 종속
  - US1과 US2는 P1 우선순위이므로 먼저 완료 (MVP)
  - US3-US6은 US1-US2 완료 후 순차 또는 병렬 진행 가능
- **다듬기 (Phase 9)**: 원하는 모든 사용자 스토리 완료에 종속

### 사용자 스토리 종속성

- **사용자 스토리 1 (P1)**: 기초 작업 (Phase 2) 후 시작 가능 - 다른 스토리에 대한 종속성 없음
- **사용자 스토리 2 (P1)**: US1 완료 후 시작 가능 (블로그 배포 필요)
- **사용자 스토리 3 (P2)**: US2 완료 후 시작 가능 (포스트 필요)
- **사용자 스토리 4 (P2)**: US1 완료 후 시작 가능 (테마 테스트용)
- **사용자 스토리 5 (P3)**: US2 완료 후 시작 가능 (포스트 필요)
- **사용자 스토리 6 (P3)**: US1 완료 후 시작 가능 (독립적)

### 각 사용자 스토리 내

- 정적 사이트 특성상 순차 실행 권장 (파일 생성 → 로컬 테스트 → 배포)
- 일부 작업은 병렬 가능 ([P] 표시):
  - 여러 포스트 파일 동시 작성 가능
  - README, .gitignore 등 독립 파일 동시 수정 가능

### 병렬 기회

- [P]로 표시된 모든 설정 작업은 병렬로 실행 가능 (T001, T002)
- 여러 포스트 파일 동시 작성 가능 (T009, T010, T011)
- 여러 페이지 파일 동시 작성 가능 (T033, T034)
- 문서화 작업 병렬 수행 가능 (T037, T038, T039)

## 참고사항

- [P] 작업 = 다른 파일, 종속성 없음
- [Story] 레이블은 추적을 위해 작업을 특정 사용자 스토리에 매핑
- 각 사용자 스토리는 독립적으로 완료 및 테스트 가능해야 함
- 정적 사이트이므로 자동화된 단위 테스트 대신 수동 브라우저 테스트 사용
- 각 단계 완료 후 커밋 권장
- 체크포인트에서 중단하여 스토리를 독립적으로 검증
- 피해야 할 것: 모호한 작업, Git 충돌, 빌드 실패를 야기하는 설정 오류
